# Requirements Document

## Introduction

This feature adds a property-based test suite to RecallIQ using `fast-check` and `vitest`. The suite validates seven mathematical and structural properties that are central to the app's correctness. All properties are pure (no DOM, React, or network), run in a Node environment, and use `fast-check` arbitraries. The implementation touches only `vite.config.ts`, `package.json`, and a new `src/properties.test.ts` file.

## Glossary

- **PBT Suite**: The property-based test suite implemented in `src/properties.test.ts`
- **Property**: A universally-quantified assertion that must hold for all values generated by a given arbitrary
- **Arbitrary**: A `fast-check` generator that produces random typed values for testing
- **Question**: The `Question` interface from `src/types/index.ts` — a multiple-choice item with `choices` array and `correctAnswerIndex`
- **Score**: An integer in `[0, 10]` representing how many out of 10 questions a user answered correctly in a session
- **Accuracy**: A derived percentage computed as `(score / 10) * 100`, always in `[0, 100]`
- **Vitest**: The test runner configured via `vite.config.ts`
- **fast-check**: The property-based testing library used for input generation and shrinking

## Requirements

### Requirement 1

**User Story:** As a developer, I want vitest configured so that I can run the property tests with a single command.

#### Acceptance Criteria

1. THE `vite.config.ts` file SHALL include a `test` block with `globals: true` and `environment: 'node'`.
2. THE `package.json` file SHALL include a `"test"` script whose value is `"vitest --run"`.

---

### Requirement 2

**User Story:** As a developer, I want fraction-to-percentage conversion validated, so that the derived accuracy display is always mathematically correct.

#### Acceptance Criteria

1. WHEN given any integer numerator in `[0, 100]` and any positive integer denominator in `[1, 100]`, THE PBT Suite SHALL assert that `(numerator / denominator) * 100` equals `(numerator * 100) / denominator`.

---

### Requirement 3

**User Story:** As a developer, I want squaring validated over the app's relevant integer range, so that any future use of `n²` in the app is known to be correct.

#### Acceptance Criteria

1. WHEN given any integer `n` in `[1, 30]`, THE PBT Suite SHALL assert that `square(n) === n * n`.

---

### Requirement 4

**User Story:** As a developer, I want cubing validated over the app's relevant integer range, so that any future use of `n³` in the app is known to be correct.

#### Acceptance Criteria

1. WHEN given any integer `n` in `[1, 20]`, THE PBT Suite SHALL assert that `cube(n) === n * n * n`.

---

### Requirement 5

**User Story:** As a developer, I want the sqrt-of-square identity validated, so that round-trip numeric transforms are guaranteed over non-negative integers.

#### Acceptance Criteria

1. WHEN given any integer `n` in `[0, 30]`, THE PBT Suite SHALL assert that `Math.round(Math.sqrt(n * n)) === n`.

---

### Requirement 6

**User Story:** As a developer, I want session scores validated as always within bounds, so that the UI never renders an out-of-range score.

#### Acceptance Criteria

1. WHEN given any integer score in `[0, 10]`, THE PBT Suite SHALL assert that the score is greater than or equal to `0` and less than or equal to `10`.

---

### Requirement 7

**User Story:** As a developer, I want accuracy percentages validated as always within `[0, 100]`, so that the progress display is always a valid percentage.

#### Acceptance Criteria

1. WHEN given any integer score in `[0, 10]`, THE PBT Suite SHALL assert that `(score / 10) * 100` is greater than or equal to `0` and less than or equal to `100`.

---

### Requirement 8

**User Story:** As a developer, I want every Question object validated so that its `correctAnswerIndex` is always a valid index into its `choices` array.

#### Acceptance Criteria

1. WHEN given any `Question`-shaped object whose `choices` array has length in `[2, 6]` and whose `correctAnswerIndex` is in `[0, choices.length - 1]`, THE PBT Suite SHALL assert that `correctAnswerIndex >= 0` and `correctAnswerIndex < choices.length`.
